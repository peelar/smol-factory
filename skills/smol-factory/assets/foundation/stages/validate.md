# Validate the submission

Onboarding adds repository-specific references to this stage in `policy.ts`.
Read those documents and the stage's enabled requirement IDs before assessment.

Check submission format, required information and contribution eligibility using
the configured requirements. Report exactly what is missing or contrary to an
accepted rule. An unfamiliar format is not automatically invalid. If no format
rule is configured, do not invent one; distinguish insufficient evidence from a
format violation. A required linked issue is a repository setting, not a default.

Use the requirement's configured failure outcome. Missing information normally
needs clarification; an explicit eligibility exclusion can support rejection.
Neither authorizes a GitHub comment or closure. A rejection is a local assessment
until an exact public action is approved or covered by an accepted grant.

Do not execute code. Produce an evidence-backed stage result and update our
understanding. Pass only when the applicable requirements are met.
